**Стек:** HTML, SCSS, TypeScript, Vite.

## Структура проекта

- `src/` — исходные файлы проекта;
- `src/components/` — компоненты приложения;
- `src/components/base/` — базовые классы и инфраструктурный код;
- `src/components/Models/` — модели данных;
- `src/types/` — типы и интерфейсы TypeScript;

- `src/scss/` — стили приложения.

- `index.html` — HTML-разметка главной страницы;
- `src/main.ts` — точка входа приложения;
- `src/types/index.ts` — типы и интерфейсы;
- `src/scss/styles.scss` — основной файл стилей;
- `src/utils/constants.ts` — константы приложения;
- `src/utils/utils.ts` — вспомогательные функции.

npm install

Для запуска проекта в режиме разработки:

Для сборки проекта выполните:

```bash

```

Или:

```bash
yarn build
```

Результат production-сборки размещается в папке `dist/`.

# Интернет-магазин «Веб-ларёк»

«Веб-ларёк» — интернет-магазин товаров для веб-разработчиков. Пользователь может просматривать каталог, открывать карточки товаров, добавлять товары в корзину, удалять их и оформлять заказ.

Оформление заказа включает выбор способа оплаты, ввод адреса доставки, указание контактных данных и отправку заказа на сервер.

## 1. Архитектура приложения

Приложение построено на основе архитектуры MVP (Model–View–Presenter).

Архитектура разделяет приложение на три слоя:

- **Model** — хранит и изменяет данные приложения.
- **View** — отвечает за отображение данных и взаимодействие пользователя с интерфейсом.
- **Presenter** — связывает модели и представления, обрабатывает события и управляет логикой приложения.

Взаимодействие между слоями организовано с помощью брокера событий `EventEmitter`.

Модели и компоненты представления сообщают об изменениях и действиях пользователя посредством событий. Presenter подписывается на эти события, выполняет необходимые действия и обновляет интерфейс.

## 2. Типы и интерфейсы

Все основные типы приложения находятся в файле `src/types/index.ts`.

### Интерфейс IProduct

Описывает товар каталога:

- `id: TProductId` — уникальный идентификатор;
- `title: string` — название;
- `description: string` — описание;
- `image: string` — путь к изображению;
- `category: string` — категория;
- `price: number | null` — цена товара или `null`, если товар недоступен для покупки.

### Интерфейс IBuyer

Описывает данные покупателя:

- `payment: TPayment | null` — способ оплаты;
- `email: string` — электронная почта;
- `phone: string` — телефон;
- `address: string` — адрес доставки.

### Другие типы

- `TPayment` — допустимые способы оплаты: `cash` или `card`;
- `TProductId` — тип идентификатора товара;
- `IProductResponse` — структура ответа сервера с каталогом товаров;
- `ICreateOrderRequest` — данные, передаваемые серверу при оформлении заказа;
- `IOrderResponse` — ответ сервера после создания заказа;
- `IApi` — интерфейс методов взаимодействия с API;
- `ApiPostMethods` — допустимые HTTP-методы для отправки данных.

## 3. Базовый код

### 3.1. Класс Component

Файл: `src/components/base/Component.ts`

Абстрактный базовый класс для компонентов представления. Реализует общую функциональность работы с DOM.

Класс является обобщённым и принимает тип `T`, описывающий данные компонента.

**Конструктор:**

`constructor(container: HTMLElement)` — принимает корневой DOM-элемент компонента.

**Поле:**

- `container: HTMLElement` — корневой DOM-элемент.

**Методы:**

- `render(data?: Partial<T>): HTMLElement` — обновляет свойства компонента переданными данными и возвращает корневой DOM-элемент;
- `setImage(element: HTMLImageElement, src: string, alt?: string): void` — устанавливает изображение и альтернативный текст.

### 3.2. Класс Api

Файл: `src/components/base/Api.ts`

Базовый класс для выполнения HTTP-запросов к серверу.

**Основные возможности:**

- выполнение GET-запросов;
- отправка данных POST, PUT и DELETE-запросами;
- обработка ответов сервера;
- проверка успешности запросов.

Класс реализует интерфейс `IApi`.

Основные методы:

- `get<T>(uri: string): Promise<T>` — получает данные с сервера;
- `post<T>(uri: string, data: object, method?: ApiPostMethods): Promise<T>` — отправляет данные на сервер;
- `handleResponse(response: Response): Promise<object>` — обрабатывает ответ сервера.

### 3.3. Класс EventEmitter

Файл: `src/components/base/Events.ts`

Брокер событий реализует паттерн «Наблюдатель» и обеспечивает взаимодействие между моделями, представлениями и Presenter.

**Поле:**

- `_events: Map<string | RegExp, Set<Function>>` — хранит подписки на события и обработчики.

**Методы:**

- `on(event, callback)` — подписывает обработчик на событие;
- `emit(event, data?)` — инициирует событие и передаёт данные обработчикам;
- `trigger(event, context?)` — создаёт функцию для вызова события с заданным контекстом;
- `off(event, callback)` — удаляет подписку;
- `offAll()` — удаляет все подписки;
- `onAll(callback)` — подписывает обработчик на все события.

## 4. Модели данных (Model)

Модели находятся в папке `src/components/Models/`.

### 4.1. Модель Catalog

Файл: `src/components/Models/Catalog.ts`

Отвечает за хранение каталога товаров и выбранного пользователем товара.

**Поля:**

- `products: IProduct[]` — список товаров;
- `selectedProduct: IProduct | null` — выбранный товар.

**Конструктор:**

`constructor(events: IEvents)` — принимает брокер событий.

**Методы:**

- `setProducts(products: IProduct[]): void` — сохраняет список товаров и генерирует событие `catalog:changed`;
- `getProducts(): IProduct[]` — возвращает список товаров;
- `getProduct(id: TProductId): IProduct | undefined` — находит товар по идентификатору;
- `setSelectedProduct(product: IProduct): void` — сохраняет выбранный товар и генерирует событие `catalog:selected`;
- `getSelectedProduct(): IProduct | null` — возвращает выбранный товар.

### 4.2. Модель Basket

Файл: `src/components/Models/Basket.ts`

Отвечает за хранение товаров, добавленных пользователем в корзину.

**Поле:**

- `products: IProduct[]` — список товаров в корзине.

**Конструктор:**

`constructor(events: IEvents)` — принимает брокер событий.

**Методы:**

- `getProducts(): IProduct[]` — возвращает список товаров;
- `addProduct(product: IProduct): void` — добавляет товар и генерирует событие `basket:changed`;
- `removeProduct(id: TProductId): void` — удаляет товар по идентификатору и генерирует событие `basket:changed`;
- `clear(): void` — очищает корзину и генерирует событие `basket:changed`;
- `getTotal(): number` — рассчитывает общую стоимость товаров;
- `getCount(): number` — возвращает количество товаров;
- `hasProduct(id: TProductId): boolean` — проверяет наличие товара в корзине.

### 4.3. Модель Buyer

Файл: `src/components/Models/Buyer.ts`

Хранит данные покупателя, необходимые для оформления заказа.

**Поле:**

- `buyer: IBuyer` — объект с данными покупателя.

**Конструктор:**

`constructor(events: IEvents)` — принимает брокер событий.

**Методы:**

- `setPayment(payment: IBuyer['payment']): void` — устанавливает способ оплаты;
- `setEmail(email: string): void` — сохраняет электронную почту;
- `setPhone(phone: string): void` — сохраняет телефон;
- `setAddress(address: string): void` — сохраняет адрес доставки;
- `getBuyer(): IBuyer` — возвращает данные покупателя;
- `clear(): void` — сбрасывает данные покупателя;
- `validate(): Partial<Record<keyof IBuyer, string>>` — проверяет заполненность обязательных полей и возвращает ошибки.

При изменении данных модель генерирует событие `buyer:changed`.

## 5. Слой коммуникации с сервером

### Класс ApiService

Файл: `src/components/ApiService.ts`

Отвечает за взаимодействие приложения с API.

Получает экземпляр класса `Api` через конструктор, используя композицию.

**Конструктор:**

`constructor(api: IApi)` — принимает объект, реализующий интерфейс `IApi`.

**Методы:**

- `getProducts(): Promise<IProductResponse>` — получает каталог товаров с сервера по адресу `/product/`;
- `createOrder(order: ICreateOrderRequest): Promise<IOrderResponse>` — отправляет данные заказа на сервер по адресу `/order/`.

Адрес сервера задаётся через переменную окружения `VITE_API_ORIGIN`.

Полученные товары передаются в модель `Catalog`.

Компоненты представления находятся в папке `src/components/`.

Они отвечают за отображение данных и взаимодействие пользователя с интерфейсом. Компоненты используют базовый класс `Component`, если требуется общая функциональность работы с DOM.

## 7. Презентер (Presenter)

Файл: `src/components/Presenter.ts`

Класс `Presenter` связывает модели данных, компоненты представления и сервис взаимодействия с сервером.

Получает необходимые зависимости через конструктор:

- `events: IEvents` — брокер событий;
- `catalog: Catalog` — модель каталога;
- `basket: Basket` — модель корзины;
- `buyer: Buyer` — модель покупателя;
- `apiService: ApiService` — сервис работы с сервером;
- `page: Page` — представление главной страницы;
- `modal: Modal` — модальное окно.

**Основные обязанности Presenter:**

- подписка на события приложения;
- обработка выбора товара;
- отображение каталога;
- добавление и удаление товаров из корзины;
- обновление счётчика товаров;
- отображение корзины;
- управление этапами оформления заказа;
- проверка данных покупателя;
- отправка заказа на сервер;
- отображение результата оформления заказа;
- очистка данных после успешного заказа.

Presenter использует модели для получения и изменения данных, а компоненты View — для отображения информации и обработки действий пользователя.

## 8. Основные сценарии работы приложения

### Просмотр каталога

1. Приложение запрашивает товары у сервера через `ApiService`.
2. Полученные товары сохраняются в модели `Catalog`.
3. Генерируется событие `catalog:changed`.
4. Presenter создаёт карточки товаров и передаёт их компоненту `Page`.

### Просмотр товара

1. Пользователь выбирает карточку каталога.
2. Presenter получает данные выбранного товара.
3. Создаётся компонент `CardPreview`.
4. Карточка отображается в модальном окне.

### Работа с корзиной

1. Пользователь добавляет товар в корзину.
2. Модель `Basket` обновляет список товаров.
3. Генерируется событие `basket:changed`.
4. Presenter обновляет счётчик и отображение корзины.

Удаление товара выполняется аналогичным образом.

### Оформление заказа

Первый этап:

- выбор способа оплаты;
- ввод адреса доставки;
- проверка заполненности обязательных полей;
- переход ко второму этапу только при корректном заполнении.

Второй этап:

- ввод электронной почты;
- ввод телефона;
- проверка заполненности полей;
- отправка заказа на сервер при корректном заполнении.

### Завершение заказа

1. Presenter отправляет заказ через `ApiService`.
2. Сервер возвращает результат оформления.
3. Отображается компонент `Success` с итоговой суммой.
4. После нажатия кнопки возврата к покупкам закрывается модальное окно.
5. Корзина и данные покупателя очищаются.

## 9. События приложения

Основные события, используемые для взаимодействия компонентов:

- `catalog:changed` — изменился список товаров;
- `catalog:selected` — выбран товар;
- `basket:changed` — изменилось содержимое корзины;
- `basket:open` — открытие корзины;
- `basket:checkout` — переход к оформлению заказа;
- `buyer:changed` — изменились данные покупателя;
- `payment:changed` — изменился способ оплаты;
- `address:changed` — изменился адрес доставки;
- `email:changed` — изменился email;
- `phone:changed` — изменился телефон;
- `order:submit` — переход от первой формы ко второй;
- `order:finish` — завершение заполнения форм и отправка заказа.

Дополнительно компоненты представления используют callback-функции для передачи действий пользователя в Presenter.

## 10. Итог

Приложение реализовано с разделением ответственности между слоями Model, View и Presenter. Модели отвечают за данные, представления — за отображение и взаимодействие с пользователем, а Presenter координирует работу приложения.

Для взаимодействия с сервером используется отдельный сервис `ApiService`, а для обмена событиями — брокер `EventEmitter`.

Такая структура упрощает поддержку, тестирование и дальнейшее развитие приложения.
