# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.
### 3.1. Интерфейсы

Интерфейс `IProduct` описывает структуру товара, `IBuyer` — данные покупателя. `IProductResponse` используется для описания ответа с каталогом товаров.

Для оформления заказа создан `ICreateOrderRequest`, который содержит данные покупателя, список выбранных товаров и итоговую стоимость. `IOrderResponse` описывает данные, которые возвращает сервер после создания заказа.

Таким образом, на этом этапе определены типы данных, которые будут использоваться в моделях приложения и при взаимодействии с API.

### 3.2. Создание моделей данных

Для работы с данными приложения были созданы три модели: `Catalog`, `Basket` и `Buyer`. Каждая модель отвечает за отдельную область данных приложения.

#### Модель `Catalog`

Файл: `src/components/Models/Catalog.ts`

Модель `Catalog` хранит список всех товаров и выбранный пользователем товар.

**Поля:**

* `products: IProduct[]` — список всех товаров;
* `selectedProduct: IProduct | null` — выбранный товар или `null`, если товар не выбран.

**Методы:**

* `setProducts(products: IProduct[]): void` — сохраняет список товаров;
* `getProducts(): IProduct[]` — возвращает список всех товаров;
* `getProduct(id: string): IProduct | undefined` — находит товар по `id` и возвращает его или `undefined`, если товар не найден;
* `setSelectedProduct(product: IProduct): void` — сохраняет выбранный товар;
* `getSelectedProduct(): IProduct | null` — возвращает выбранный товар или `null`, если товар не выбран.

#### Модель `Basket`

Файл: `src/components/Models/Basket.ts`

Модель `Basket` отвечает за хранение товаров, добавленных пользователем в корзину.

**Поле:**

* `products: IProduct[]` — список товаров, добавленных в корзину.

**Методы:**

* `getProducts(): IProduct[]` — возвращает список товаров корзины;
* `addProduct(product: IProduct): void` — добавляет товар в корзину;
* `removeProduct(id: string): void` — удаляет товар из корзины по `id`;
* `clear(): void` — очищает корзину;
* `getTotal(): number` — рассчитывает и возвращает общую стоимость товаров в корзине;
* `getCount(): number` — возвращает количество товаров в корзине;
* `hasProduct(id: string): boolean` — проверяет наличие товара в корзине по `id`.

**#### Модель `Buyer`**

Файл: `src/components/Models/Buyer.ts`

Модель `Buyer` хранит данные покупателя, необходимые для оформления заказа.

****Поле:****

* `buyer: IBuyer` — объект с данными покупателя: способом оплаты, email, телефоном и адресом.

****Методы:****

* `setPayment(payment: IBuyer['payment']): void` — сохраняет выбранный способ оплаты;

* `setEmail(email: string): void` — сохраняет email покупателя;

* `setPhone(phone: string): void` — сохраняет номер телефона;

* `setAddress(address: string): void` — сохраняет адрес покупателя;

* `getBuyer(): IBuyer` — возвращает все данные покупателя;

* `clear(): void` — очищает данные покупателя и возвращает их к начальному состоянию;

* `validate(): Partial<Record<keyof IBuyer, string>>` — проверяет заполненность обязательных полей и возвращает объект с сообщениями об ошибках.


### 3.3. Слой коммуникации

Для взаимодействия с сервером создан класс `ApiService`, который получает экземпляр `IApi` через конструктор. Благодаря композиции класс использует методы `get` и `post` для выполнения запросов к серверу.

Класс содержит два метода:

* `getProducts()` — выполняет GET-запрос на эндпоинт `/product/` и возвращает объект с общим количеством товаров и массивом товаров;
* `createOrder()` — выполняет POST-запрос на эндпоинт `/order/`, передаёт данные покупателя и выбранных товаров и возвращает объект с идентификатором заказа и его итоговой стоимостью.

Для работы с сервером используется готовый класс `Api`, реализующий интерфейс `IApi`.

Адрес API задаётся через переменную окружения `VITE_API_ORIGIN`.

Полученные с сервера товары передаются в модель `Catalog`, которая сохраняет и предоставляет доступ к каталогу товаров.

Таким образом, класс `ApiService` отвечает только за обмен данными с сервером и не занимается хранением или отображением данных.
### 3.4. Слой представления (View)

Слой View отвечает за отображение данных приложения и взаимодействие пользователя с интерфейсом. Компоненты представления наследуются от базового класса `Component`, если это необходимо для использования общей функциональности работы с DOM.

Компоненты не содержат бизнес-логику приложения. При действиях пользователя они генерируют события, которые обрабатываются слоем Presenter.

#### Базовый класс `Component<T>`

Файл: `src/components/base/Component.ts`

Базовый абстрактный класс для компонентов интерфейса. Содержит общий механизм отображения DOM-элементов и установки изображений.

**Поля:**
- `container: HTMLElement` — корневой DOM-элемент компонента.

**Методы:**
- `render(data?: Partial<T>): HTMLElement` — обновляет свойства компонента переданными данными и возвращает корневой DOM-элемент.
- `setImage(element: HTMLImageElement, src: string, alt?: string): void` — устанавливает изображение и альтернативный текст.

#### Класс `Page`

Отвечает за отображение главной страницы магазина.

**Поля:**

- `_counter: HTMLElement` — DOM-элемент со счётчиком товаров в корзине.
- `_catalog: HTMLElement` — DOM-элемент каталога товаров.
- `_wrapper: HTMLElement` — DOM-элемент обёртки страницы.

**Сеттеры:**

- `set counter(value: number): void` — обновляет счётчик товаров в корзине.
- `set catalog(items: HTMLElement[]): void` — отображает карточки товаров в каталоге.
- `set locked(value: boolean): void` — включает или снимает блокировку страницы при открытом модальном окне.

#### Базовый класс `Card<T>`

Родительский класс карточек товаров. Содержит общую функциональность для работы с заголовком и ценой товара.

**Поля:**

- `title: HTMLElement` — DOM-элемент для отображения названия товара.
- `price: HTMLElement` — DOM-элемент для отображения цены товара.

**Сеттеры:**

- Сеттер для установки названия товара.
- Сеттер для установки цены товара.

#### Класс `CardCatalog`

Отвечает за отображение карточки товара в каталоге на основе шаблона `#card-catalog`.

**Поля:**
- `image: HTMLImageElement` — изображение товара.
- `category: HTMLElement` — категория товара.

**Методы:**
- Сеттеры для установки изображения, категории, названия и цены товара.

**Событие:** `card:select` — пользователь выбирает карточку для просмотра подробной информации.

#### Класс `CardPreview`

Отвечает за отображение подробной информации о товаре на основе шаблона `#card-preview`.

**Поля:**
- `image: HTMLImageElement` — изображение товара.
- `category: HTMLElement` — категория товара.
- `description: HTMLElement` — описание товара.
- `button: HTMLButtonElement` — кнопка добавления товара в корзину.

**Методы:**

**Событие:** `card:buy` — пользователь добавляет товар в корзину.

#### Класс `CardBasket`

Отвечает за отображение товара в корзине на основе шаблона `#card-basket`.

**Поля:**
- `index: HTMLElement` — порядковый номер товара.

**Методы:**
- Сеттер для установки порядкового номера.

#### Класс `BasketView`

Отвечает за отображение содержимого корзины на основе шаблона `#basket`.

- `open(): void` — открывает модальное окно.

**События:**

#### Взаимодействие с Presenter

Presenter связывает компоненты View с моделями `Catalog`, `Basket`, `Buyer` и сервисом `ApiService`.

Он обрабатывает события выбора товара, добавления и удаления товаров из корзины, открытия и закрытия модального окна, отправки форм и завершения заказа. После изменения данных Presenter обновляет соответствующие компоненты View.

Компоненты View отвечают за отображение данных и передачу пользовательских действий через события. Проверка данных, изменение моделей и взаимодействие с сервером выполняются вне слоя View.
### 3.5. Презентер (Presenter)

Для реализации логики приложения создан отдельный класс `Presenter`, расположенный в файле `src/components/Presenter.ts`.

Презентер является связующим звеном между слоями Model и View. Он получает необходимые зависимости через конструктор: брокер событий `EventEmitter`, модели `Catalog`, `Basket`, `Buyer` и компонент `Page`.

**Основные обязанности Presenter:**

- обработка событий, поступающих от моделей данных и компонентов представления;
- получение данных из моделей и передача их компонентам представления;
- создание карточек товаров на основе шаблонов HTML;
- управление отображением выбранного товара, корзины и форм оформления заказа;
- организация взаимодействия с API при оформлении заказа.

Для взаимодействия между слоями используется брокер событий `EventEmitter`. Модели и компоненты представления сообщают об изменениях данных и действиях пользователя посредством событий. Презентер подписывается на эти события и выполняет соответствующие действия.

При изменении данных модели Presenter получает актуальные данные и обновляет соответствующие компоненты представления. Отображение также обновляется при открытии модальных окон.

Презентер не содержит собственной логики генерации событий: он обрабатывает события, поступающие от моделей и представлений.

Выбранная архитектура позволяет разделить ответственность между слоями приложения, уменьшить связанность компонентов и упростить дальнейшее развитие и тестирование проекта.
